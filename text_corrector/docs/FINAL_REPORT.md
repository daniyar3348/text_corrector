# Turan Text Corrector — итоговый отчёт по проекту

**Дата:** 2026-06-20. **Статус:** проект реализован, пилот развёрнут и принят.

---

## 1. Назначение и цель
Автоматический корректор орфографии **казахского** текста. Целевой результат —
«единый механизм» коррекции: нейросетевой **детектор ошибок** + **корректор**,
дополненный морфологической валидацией. Русский язык — вне фокуса (pass-through,
без обученной модели).

## 3. Архитектура решения
```
Текст → Определение языка (russify-lexicon сигнал)
          ├─ Русский  → pass-through (без изменений)
          └─ Казахский → KazRoBERTa-ДЕТЕКТОР (token-classification: KEEP/ERROR по токенам)
                          → КОРРЕКТОР (инверсные правила ru↔kk + лексикон 174k + OSA edit-distance)
                          → морфоанализатор (защита валидных форм от переисправления)
                          → исправленный текст
```
- **Детектор:** дообученный `kz-transformers/kaz-roberta-conversational` (token-classification, 6 слоёв / 12 голов / vocab 52k).
- **Корректор:** символьный (инверсия ka2ru/сингармонизма + лексикон + OSA), быстрый, без GPU.
- **API:** `POST /correct-text`, `POST /detect-language`, `GET /health`.

## 4. Данные и обучение (этап 4)
- Источник: корпус `merged_dissertation.json` (568 МБ, 93 218 казахских статей).
- Очистка: нормализация букв-двойников (`ə→ә`, `ћ→һ`), сегментация (фикс склеек), удаление иноязычных вставок, мягких переносов/PUA → **922 798 чистых предложений**.
- Синтетические ошибки (ka2ru, сингармонизм, swap, drop, dup, sub) + аугментация ×3 → **2.57 млн обучающих пар**; ~11% «чистых» (против переисправления); 0 утечки между train/val/test.
- Обучение детектора — на GPU (Colab), 2 эпохи.

## 5. Показатели качества (test, 8000 примеров)

| Метрика | Значение |
|---|---|
| **Детекция ошибок (F1)** | **97.3%** (precision 97.1 / recall 97.4) |
| **Сквозная коррекция** (предложений идеально) | **80.5%** |
| Корректор при идеальной детекции (oracle) | 88% слов, точность изменений 91.6% |
| Baseline без ML (эвристика+корректор) | F1 86.3% / сквозь 64.6% |
| Потолок (oracle-детекция) | 83.5% |

**Производительность:** тёплый запрос ~9 мс; под нагрузкой ~150–200 req/s (CPU-bound); контейнер ~373 МБ RAM.

## 6. Развёртывание и эксплуатация (этап 5)
- **Docker-образ** `turan-serve` (2.84 ГБ, linux/arm64): CPU-torch, модель и лексикон вшиты; healthcheck проверяет загрузку **реальной** модели (а не заглушки); non-root.
- **Автоматизация:** `scripts/deploy.sh` (colima → build → run → gate → smoke) + субагент `.claude/agents/turan-deploy.md`.
- **Запуск:** локально (uvicorn, Python 3.13 + torch) или Docker (`bash backend/scripts/deploy.sh`, `BACKEND_PORT=8010 docker-compose up`).
- Пилот развёрнут локально, адверсариально провалидирован (целостность модели, устойчивость к крайним входам, resilience после рестарта — всё PASS).

## 7. Ограничения и зона ответственности
- **OOV** (редкие имена, неологизмы, термины вне лексикона) — не исправляются; failure mode **безопасный** (слово остаётся как есть, не калечится).
- **Короткие обрывки (1–2 слова)** — детектор слабее (обучен на предложениях); язык определяется, но коррекция изолированного слова менее надёжна.
- **Корпус-дескриптивность:** лексикон собран из реальных текстов, поэтому редкие «ошибочные» написания, реально встречающиеся в корпусе (напр. `салем` freq 6), считаются валидными.
- **drop/sub** ошибки чинятся слабее (~62/70%) — неоднозначны без контекста.
- **Русский** — pass-through (исправлений нет).
- **Пропускная способность** ~200 req/s на CPU.
- **Итог:** инструмент предредактуры; финальная вычитка человеком обязательна.

## 8. Рекомендации по применению и масштабированию
- **Применение:** образование (проверка работ/материалов), госорганы и делопроизводство, СМИ/издательства — для казахоязычного текста.
- **Интеграция:** через REST API; проверять `GET /health` (модель = `TransformerModel`); лимит текста 5000 символов.
- **Масштабирование:** `uvicorn --workers N` (по ядрам/памяти, каждый воркер — копия модели), GPU/батчинг для высокой нагрузки.
- **Улучшения (перспективы):** нормативный словарь / apertium-FST для OOV и коротких слов (отдельный словарный модуль для ввода ≤2 слов); контекстное переранжирование для drop/sub; порог уверенности детектора; полноценная русская модель.
