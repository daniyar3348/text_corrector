# Turan Text Corrector — отчёт о пилотной системе (этап 5)

**Дата:** 2026-06-20. **Статус:** пилот запущен, принят, метрики зафиксированы.

## 1. Что развёрнуто
Пилотная система автоматической коррекции **казахского** текста = «единый механизм»:
**KazRoBERTa-детектор ошибок** (token-classification) → **корректор** (инверсные правила
`ru↔kk` + лексикон 174k + OSA edit-distance). FastAPI-сервис, эндпоинты:
- `GET /health` — статус + какая модель загружена;
- `POST /detect-language` — определение языка;
- `POST /correct-text` `{"text": "..."}` — исправление (возвращает `corrected_text`, `detected_language`, `corrections`, `processing_time_ms`).

Русский язык обслуживается прежним словарным placeholder'ом (вне фокуса пилота).

## 2. Как запустить

**Локально (без Docker), torch-окружение Python 3.13:**
```bash
cd backend
KAZAKH_MODEL_PATH=$PWD/models/kazakh_detector \
  ./.venv-train/bin/uvicorn app.main:app --host 127.0.0.1 --port 8010 [--workers 4]
```
(порт 8000 на этой машине занят другим проектом — используем 8010.)

**Docker** (когда доступен daemon; файлы готовы и вычитаны):
```bash
docker build -f backend/Dockerfile.serve -t turan-serve ./backend
BACKEND_PORT=8010 docker-compose up        # backend → Dockerfile.serve, модель в образе
```
Гейт после сборки: в логах `TransformerModel (detector+corrector) loaded`, контейнер healthy
(healthcheck падает, если модель тихо деградировала до placeholder).

## 3. Метрики функционирования

### Качество (на отложенном test, 8000 примеров)
| Метрика | Значение |
|---|---|
| Детекция ошибок (KazRoBERTa), F1 | **97.3%** (P 97.1 / R 97.4) |
| Сквозная коррекция (предложений исправлено полностью) | **80.5%** |
| Корректор при oracle-детекции (потолок) | 88% слов, точность изменений 91.6% |
| Baseline без ML (эвристика+корректор) | F1 86.3% / 64.6% |

### Производительность (живой сервер, нагрузка)
| Конфигурация | Throughput | p50 | p99 |
|---|---|---|---|
| 1 воркер, тёплый одиночный запрос | — | **~9 мс** | — |
| 1 воркер, конкурентность 20 | ~150–190 req/s | ~120–150 мс | ~200 мс |
| 4 воркера, конкурентность 20 | ~200 req/s | **85 мс** | ~270 мс |

**Потолок CPU ≈200 req/s** (инференс-bound) — достаточно для пилота; для роста нужен GPU/больше воркеров.

## 4. Баг, найденный и устранённый при приёмке
Приёмка вскрыла дефект роутинга: казахские предложения **без спецбукв** (а ka2ru-ошибки
как раз стирают `қ→к`, `ә→а`…) определялись как русские и портились русским placeholder'ом.
**Исправлено:** в `language_detection.py` добавлен сигнал «покрытие казахским лексиконом после
russify-маппинга» (нелинейный, на предложениях ≥3 слов) — теперь ka2ru-казахский корректно
уходит в казахский пайплайн. Пример: `Бул маселе оте манызды болып тур` → `Бұл мәселе өте
маңызды болып тұр`. Все 48 тестов проекта проходят.

## 5. Известные ограничения
- **OOV:** редкие имена/неологизмы вне лексикона корректор не починит (оставит как есть — не калечит).
- **Короткие обрывки** (1–2 слова без спецбукв): язык определить трудно → возможен мисроутинг.
- **drop/sub** ошибки чинятся слабее (62/70%) — неоднозначны без контекста.
- **Русский** обслуживает только placeholder (тонкий словарь) — вне фокуса пилота.
- **Пропускная способность** ~200 req/s на CPU.
