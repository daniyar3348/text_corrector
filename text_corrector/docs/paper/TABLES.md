# Tables

This section collects the quantitative results of the study. All figures are taken from the verified project artefacts (the dataset `meta.json`, the fine-tuned checkpoint, the evaluation scripts, and the project work log and pilot report). Detection and end-to-end evaluation are reported on the test set, using an 8,000-sentence subset where indicated. Corrector accuracy is reported under oracle (perfect) detection so as to isolate the correction stage from the detection stage. Where a value referenced in earlier project documentation could not be located in a verifiable source, it is marked "[TODO: verify]".

## Table 1. Dataset statistics

The dataset is a synthetic parallel corpus of (correct, corrupted) sentence pairs generated by injecting errors into cleaned Kazakh sentences. Clean (identity) pairs are retained to suppress over-correction. The error-operation mixture is dominated by the look-alike *ka2ru* class, in which Kazakh-specific Cyrillic letters are typed as visually similar standard-Russian Cyrillic letters. The realized per-error-type shares below are computed over all injected edits (the values in parentheses are the underlying edit counts); they differ from the sampling weights used during generation, which were $[\text{ka2ru } 0.45,\ \text{harmony } 0.18,\ \text{swap } 0.13,\ \text{drop } 0.10,\ \text{dup } 0.07,\ \text{sub } 0.07]$. The clean-text corpus follows the methodology of synthetic confusion-set error generation [grundkiewicz2019synthetic], and the morphologically rich Kazakh vocabulary is handled with byte-level subword tokenization [sennrich2016bpe].

## Table 2. Detection results: trained detector vs. heuristic baseline

The detection stage is a token-classification model (per-token labels KEEP / ERROR) built on the KazRoBERTa encoder [liu2019roberta; kztransformers2023kazroberta], following the tag-not-rewrite paradigm for error detection [omelianchuk2020gector; awasthi2019pie]. The heuristic baseline flags a word as erroneous when it is absent from the lexicon, in the spirit of classical nonword detection [kukich1992techniques]. Results are on the 8,000-sentence test subset. False-positive counts referenced in earlier documentation could not be located in any verifiable artefact and are therefore marked for verification.

## Table 3. End-to-end sentence-level correction

End-to-end performance is reported as the fraction of test sentences that are *fully* corrected (every error fixed, no spurious edits) on the 8,000-sentence test subset. Three configurations are compared: the heuristic baseline (no learned detection), the trained two-stage pipeline, and an oracle ceiling in which detection is perfect by construction. The trained pipeline reaches $80.5\%$, within roughly three points of the $83.5\%$ oracle ceiling, indicating that detection is essentially solved and the corrector is the remaining bottleneck.

| Configuration | Sentences fully corrected | Detection F1 |
|---|---|---|
| Heuristic baseline | $64.6\%$ | $86.3\%$ |
| Trained pipeline | $80.5\%$ | $97.3\%$ |
| Oracle ceiling (perfect detection) | $83.5\%$ | $100\%$ |

## Table 4. Per-error-type corrector accuracy under oracle detection

To isolate the correction stage, the corrector is evaluated under oracle detection on the test set: each truly erroneous word is presented to the corrector, and "fixed" denotes recovery of the gold form. The corrector generates candidates via inverse look-alike and vowel-harmony substitutions filtered by lexicon membership, with an Optimal String Alignment (restricted Damerau–Levenshtein) fallback search over the lexicon [levenshtein1966binary; damerau1964technique], guarded by a morphological analyzer [kessikbayeva2014kazakh]. Overall, $88\%$ of erroneous words are fixed at a precision-of-changes of $91.6\%$. The corrector is strongest on the lexically determined look-alike (*ka2ru*) and harmony classes and weakest on the *sub* and *drop* classes, which require contextual disambiguation not modeled here.

| Error type | Fixed (accuracy) |
|---|---|
| ka2ru | $97.6\%$ |
| harmony | $97.9\%$ |
| dup | $93\%$ |
| swap | $83\%$ |
| sub | $70\%$ |
| drop | $62\%$ |
| **Overall** | **$88\%$ fixed; $91.6\%$ precision-of-changes** |

The configuration below is the final Colab run; values not set in the training configuration use Hugging Face Trainer defaults and are annotated as such.

## Table 6. Efficiency and deployment

Latency and throughput were measured on the test Mac; the single-worker $p50$/$p99$ figures are reported as the ranges attested in the load-test results, and earlier point estimates that could not be reconciled with those ranges are marked for verification.
